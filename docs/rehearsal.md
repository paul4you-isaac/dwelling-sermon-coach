# M6 통합 리허설 기록 — Stage 0~9 (2026-11-20)

- 대상: S_20261108 (고린도후서 4:1-18). 구판(v0.4.0) 산출물을 임시 폴더에 복사해 **설교자 입력**으로만 썼습니다. 실제 볼트는 건드리지 않았습니다.
- 감독: 실제 `claude -p --plugin-dir v1.0.0 --setting-sources project`(opus). 이 설정에서 스킬은 v1.0 하나, 에이전트는 `dsc-collector`·`dsc-archivist` 둘만 보였습니다.

- 진행: 대화 두 번. Stage 0~4는 한 대화로, Stage 5~9는 **새 대화로 다시 들어와** 이어 갔습니다(「한 주 중간에 다시 들어올 때」 경로 시험).
- 비용·시간: 대화 1 $5.06 · 대화 2 $2.69, 합계 약 **$7.8**. 한 차례 응답은 26~189초.

## 리허설에서 찾아 고친 것

1. **주간 폴더가 볼트 밖 한 단계 아래에 생김.** 감독이 SKILL.md 폴더 그림을 보고 `vault_root` 뒤에 `output/`을 덧붙였습니다. 작업창은 `vault_root` 바로 아래만 보므로 이 주간을 찾지 못합니다.
   → `dsc_archive.py init`이 설정에 `vault_root`가 있으면 그 바로 아래가 아닌 폴더를 거절합니다. SKILL.md §1·§9에 「`vault_root` = output 폴더」를 적었습니다.
2. **Stage 1로 들어가도 진행 기록이 0에 머묾.** 시작 순서에 단계 올리기가 없었습니다.
   → SKILL.md §1에 수집 뒤 `advance_stage`(1)를 넣었습니다. 본문을 준 것이 설교자의 확인입니다.
3. **주동사에 수집본 쉼표가 붙어 나옴**(「ἐγκακοῦμεν,」). 주동사를 수집본 글자로 바꿔 넣을 때 문장부호까지 가져왔습니다. 작업창·생성본·묵상종합에 그대로 보였습니다.
   → 앞뒤 문장부호만 뺍니다(생략 부호 ’ ᾽ 는 남김). 읽을 때마다 다시 대조하므로 이미 저장된 `syntax.json`도 다시 고칠 필요가 없습니다.

## 고치지 않고 남긴 관찰

- 감독이 다시 들어올 때 작업창 서버 상태(`/healthz`)를 보지 않았습니다. 지침에는 있습니다. 서버가 켜져 있어 진행에는 문제가 없었습니다.
- 설교자가 「곰비스 인용문은 이번에는 빼겠다」고 하자, 감독이 `02_동행일지`의 출처 목록에 「이번 주에는 쓰지 않음」 한 줄을 더했습니다. 설교자 원문 문장은 바꾸지 않았습니다.
- 앞 페리코페를 구판은 새한글 소제목(3:12-18)으로, v1.0 수집은 개역개정 소제목(3:1-18)으로 잡았습니다. M3에서 정한 방식 그대로입니다.
- 작업창의 단계 확인 창(`confirm`)은 시험 브라우저가 자동으로 닫아, 그 한 번만 확인을 「예」로 바꿔 눌렀습니다.
