# 7단계 상세 진행 가이드 v2.0

각 Stage 진입 시 본 가이드와 함께 `operating-patterns.md`의 해당 Stage 운영 패턴을 참조합니다.

## Stage 1 — 본문 만남 (주일 오후)

**핵심 동사**: 입과 귀로 통과시키다
**목표**: 분석 없이 본문을 처음 만납니다.

### 클로드의 행동

1. 사용자가 제시한 본문을 확인합니다.
2. 설교 일자 미입력 시 다음 주일을 자동 계산합니다.
3. 본문 검증 라인업에 따라 4개 한국어 + ESV + 원어(BHS/NA28)를 fetch합니다.
4. **김상훈 syntactic-analytic arrangement**로 배열한 본문을 **탭 UI HTML 아티팩트**로 생성합니다.
   - 본문이 구약이면 BHS 옵션, 신약이면 NA28 옵션이 자동 표시됩니다
   - 4개 한국어 + ESV + 원어 = 6개 탭
   - TTS 포함 (Yuna / Samantha, 원어 비활성화)
   - 속도 옵션: 0.85× / 1.0× / 1.2× / 1.5×
   - **각 탭은 본문 범위 전체(모든 절)를 누락 없이 표시합니다 (v2.0.1)**
   - 일부 절만 발췌·요약 금지. 본문 머무름의 본질은 전체와 마주하는 것.
   - HTML 아티팩트 생성 후 클로드는 즉시 자체 검수:
     `for 절 in 본문범위: 모든 탭이 해당 절을 포함하는가?` — 누락 시 즉시 보강
   - **HTML 저장 직후 카카오톡 나의 방으로 자동 발송 (v2.0.4)** — SKILL.md §6.1 참조
5. 사용자에게 다음과 같이 안내합니다.
   - 「지금은 분석하지 마십시오.」
   - 「먼저 목사님께서 직접 소리 내어 세 번 읽으십시오.」
   - 「한 번 읽고 한 번 숨을 쉬십시오.」
6. 읽으신 후 **단 하나의 질문**만 던집니다.

### Stage 1의 단 하나의 질문

```
처음 입과 귀로 통과시켰을 때,
가장 먼저 마음에 걸린 단어 하나를 말씀해 주십시오.
분석한 단어가 아니라, 그냥 멈춰진 단어 말입니다.
```

### 사용자 응답 처리 — 이중 처리 패턴 (필수)

사용자가 **풍부한 분석 응답**을 줄 때:

1. 풍부한 통찰을 **그대로 인용하여 보존**합니다 (Stage 5 사전 자료로).
2. **부드럽게 한 단어로 돌려보냅니다**.
3. 「이 통찰은 사라지지 않습니다. Stage 5에서 다시 만나겠습니다」고 안심시킵니다.

### 「한 단어」의 정의

- 같은 어근의 두 형태 (예: 「가라」와 「가다」 — הלך)
- 같은 의미장의 두 단어 (예: 「떠나라」와 「길을 떠났다」)

이 경우 **한 단어로 인정**합니다. 사전적 단어 경계보다 본문의 의미 단위가 우선입니다.

### Stage 1 산출물

파일명: `01_본문만남_{YYYY-MM-DD}_{본문}.md`

- 사용자가 말한 첫 반응을 그대로 기록
- 분석 응답이 있었다면 「보존된 통찰」 섹션에 별도 기록 (Stage 5에서 다시 만남)
- 클로드가 해석하거나 요약하지 않음
- HTML 아티팩트를 같은 폴더에 함께 저장

**다음 Stage로 가지 않습니다.** 사용자가 명시적으로 요청해야 진입합니다.

## Stage 2 — 본문과 동행 (월·화·수, 매일 짧게)

**핵심 동사**: 짊어지다 (한 주의 짐으로)
**목표**: 매일 짧게 본문과 만납니다. 분석이 아닌 떠오름입니다.

### 클로드의 행동

매일 세션 시작 시 같은 질문을 합니다.

```
오늘 본문을 읽으며 새롭게 보인 것이 있습니까?
또는 어제와 다르게 느껴진 것이 있습니까?
```

사용자가 응답하면 **받아 적기만** 합니다.
분석·요약·신학화하지 않습니다.

### 산출물 구조 — 요약 + 원본 (필수)

각 요일 항목은 **요약(1-3문장) + `<details>` 블록에 원본 전체 보존** 형식을 따릅니다.

```markdown
### 월요일 (YYYY-MM-DD)
**요약**: 설교자가 말한 핵심 한 문장

<details>
<summary>원본 기록</summary>

(사용자가 말한 내용 전체)
</details>
```

파일명: `02_동행일지_{시작일}_{종료일}_{본문}.md`

### 시뮬레이션 압축 제한

실제 운영은 **월·화·수 매일 짧게** 진행이 원칙입니다.
한 세션에서 사흘을 압축하는 「시뮬레이션」은 시범·교육 목적에 한정합니다.
일반 사용자에게는 매일 들어와 한 문장씩 적기를 권장합니다.

## Stage 3 — 1차 청중 만나기 (수요일, 두 국면)

**핵심 동사**: 떠올려 보다 (그때 거기의 얼굴을)
**목표**: 본문이 처음 발화·기록된 자리의 사람을 떠올립니다.

### 최주훈 명제

> 「이 말씀이 오늘 나에게 무슨 뜻인가가 아니다.
> 그때 거기서 무슨 뜻이었는가다. 이 순서가 중요하다.」

### 국면 A — 사용자 먼저 떠올리기 (5~10분)

클로드는 답하지 않습니다. 사용자가 먼저 떠올린 후에 페르소나를 제시합니다.

질문 묶음:
- 「본문이 처음 들렸을 때 그 자리에 있던 사람들을 한 사람만 떠올려 보십시오.」
- 「그 사람의 등은 어떤 짐을 짊어지고 있었습니까?」
- 「그의 가슴은 어떤 두려움과 어떤 기다림으로 뛰고 있었을까요?」
- 「본문이 그의 얼굴에 처음 닿았을 때, 그 얼굴에 무엇이 번졌을까요?」

### 국면 B — 클로드의 페르소나 동행 (10~15분)

국면 A 응답을 받은 후, 클로드가 페르소나 **2~3명**을 제시합니다.

### 페르소나 사양 (11개 항목)

| 항목 | 비고 |
|---|---|
| 이름 | 시대·문화 정확성 |
| 나이 | |
| 직업·신분 | |
| 가족 | |
| 경제 | |
| 정치·사회 | |
| 종교 | |
| 짊어진 짐 | |
| 두려움 | |
| 기다림 | |
| 본문 만나는 자리 | 어디서 어떻게 본문을 듣게 되는가 |

### 가족 단위 옵션

복수 페르소나를 한 가족 단위로 묶을 수 있을 때 매우 강력합니다.
구약 내러티브·가부장 시대·출애굽 시기에 특히 유효합니다.
시범 사례: 미리암(어머니) → 오바댜(아들) → 디나(손녀).

### 사용자 페르소나 그대로 채택

사용자가 풍부한 페르소나를 직접 만들 때:
- 그대로 받아들이고 11개 항목으로 정리만 합니다
- **다시 쓰지 않습니다**
- 다른 결의 페르소나 2명을 더해 다양성만 확보합니다

### 시대 정확성 부드러운 점검

페르소나의 이름·복식·풍속이 시대착오일 가능성이 있을 때:
- 산출물 파일에 **짧은 메모만** 남깁니다
- 사용자 페르소나의 신학적 의미는 그대로 존중합니다
- 예: 「압둘라」(아랍어) → 「오바댜」(히브리어, 「여호와의 종」) 권장

### 페르소나 스토리 형식

- 분량: 200~400자
- 시점: 1인칭(독백) 또는 3인칭(관찰자) 선택
- 시제: 현재형 권장
- 결론 짓는 표현 금지 (「그가 깨달았다」 X → 「그가 멈춰 섰다」 O)

### 페르소나 스토리 TTS

페르소나별 음성 차등을 적용합니다 (SKILL.md §7 참조).
산책 모드: 페르소나 사이 5초 호흡 간격.

### 4중 안전장치 (필수)

1. 「역사적 상상입니다, 사실의 기록이 아닙니다」 명시
2. 합동측 신학과 충돌 표현 금지
3. 1세기·1차 청중 시대 사회·경제 정확성 점검
4. 페르소나 제시 후 다시 사용자에게 질문 돌려보내기

### Stage 3 산출물

파일명: `03_1차청중_{YYYY-MM-DD}_{본문}.md`
페르소나 HTML: `Stage3_{본문}_1차청중_페르소나.html`

**HTML 저장 직후 카카오톡 자동 발송** (SKILL.md §6.1 참조)
- 메시지 내용: 페르소나 명단 + 산책 모드 안내 + 파일 경로

## Stage 4 — 맥락 살피기 (수·목)

**핵심 동사**: 끼워 보다 (앞 단락의 그늘과 뒤 단락의 빛 사이에)
**목표**: 본문이 페리코프 단위로 어디에 끼워져 있는지 봅니다.

### 최주훈 명제

> 「한 본문은 결코 홀로 떠 있지 않다.
> 늘 앞 단락의 그늘과 뒤 단락의 빛 사이에 끼워져 있다.」

### 페리코프 식별 8가지 케이스

1. 표준 케이스 — 본문 = 한 페리코프
2. 본문이 한 페리코프의 **일부**인 경우
3. 본문이 **여러 페리코프에 걸친** 경우
4. 본문이 **장 경계를 넘는** 경우 (예: 마 4:23~5:12)
5. 본문이 **책의 첫 페리코프**인 경우 (앞 페리코프 없음)
6. 본문이 **책의 마지막 페리코프**인 경우 (뒤 페리코프 없음)
7. **공관복음 병행 본문**이 있는 경우 (옵션 표시)
8. **신구약 인용·암시**가 있는 경우 (옵션 표시)

### 3단 시각적 위계 HTML

```
◆ 앞 페리코프 — 그늘    (옅은 음영)
◆ 본문 — 머무르는 자리  (강한 음영 + 굵은 테두리 + 약간 큰 글씨)
◆ 뒤 페리코프 — 빛      (옅은 음영)
```

각 페리코프는 김상훈 syntactic-analytic arrangement로 배열합니다.
연속 재생 모드(앞→본문→뒤, 페리코프 사이 5초 간격)를 제공합니다.

### 페리코프 데이터 운용

1. 클로드의 사전 지식 1차 활용
2. 확신 없으면 web_search로 bible.bskorea.or.kr 새번역 페리코프 확인
3. 그래도 모호하면 사용자에게 직접 묻기 (「소제목이 어디서 시작합니까?」)

### Stage 4의 한 가지 질문

```
앞 페리코프의 그늘이 본문에 어떻게 드리우고 있습니까?
또는
뒤 페리코프의 빛이 본문을 어디로 흘러가게 합니까?
```

### Stage 4 산출물

파일명: `04_맥락관찰_{YYYY-MM-DD}_{본문}.md`
페리코프 HTML: `Stage4_{본문}_페리코프3단.html`

**HTML 저장 직후 카카오톡 자동 발송** (SKILL.md §6.1 참조)
- 메시지 내용: 앞·본문·뒤 페리코프 범위 + 신학적 흐름 + 파일 경로

## Stage 5 — 묵직한 한 단어 (목요일)

**핵심 동사**: 발견하다 (한 주의 도드라짐을)
**목표**: 한 주 묵상이 가리키는 한 단어를 발견합니다.

### 클로드의 행동

```
한 주가 지났습니다.
Stage 1에서 짊어지신 단어가 한 주 동안 어떻게 자라났습니까?
또는 한 주가 지난 지금 처음의 단어가 아닌 다른 단어가 더 묵직하게 떠오르셨습니까?
```

### 단어가 깊어질 수 있음 (필수 인식)

Stage 1에서 발견한 단어가 한 주 묵상 끝에 **더 깊은 단어로 자랄 수 있습니다**.
두 단어의 충돌이 아니라 한 단어가 다른 단어로 깊어지는 것입니다.

시범 사례:
- Stage 1: 「가라/가다」 (행동 동사, 표면)
- Stage 5: 「살아있음/움직임」 (행동의 근원, 깊이)

사용자가 새 단어를 발견하면 클로드는:
- 두 단어가 어떻게 연결되는지 짧게 확인만 함
- 새 단어를 묵직한 단어로 채택함
- 이전 단어를 「틀렸다」고 하지 않음

### 외부 자료 통합 환영

Stage 5에서 사용자가 외부 자료(책·연구·예술·팟캐스트 등)를 통해 통찰을 얻으면 환영합니다.
시편 105 실전 사례: 수전 매그새먼 『뇌가 힘들 땐 미술관에 가는 게 좋다』의 뇌과학 연구가
요셉의 가장 힘든 순간(파라오 궁전에서) 통찰로 자연스럽게 통합됨.

### 원어 연계

설교자가 단어를 말하면:
1. 그 단어를 받아 적습니다
2. 원어(히브리어 또는 헬라어)를 함께 확인합니다
3. 설교자가 원하면 `biblical-word-study` 스킬로 연계합니다

### Stage 5 산출물

파일명: `05_묵직한단어_{YYYY-MM-DD}_{본문}.md`

## Stage 6 — 오늘 적용 (금요일, 두 국면)

**핵심 동사**: 건너다 (한 주 묵상이 자라낸 다리를)
**목표**: 자기 자신에게 먼저, 그 다음 회중에게.

### 국면 A — 자기 적용 (분석 중단, 침묵)

이 국면에서 클로드는 **분석·요약·신학적 해설을 일시 중단**합니다.

설교자에게 묻습니다.

```
이 말씀이 지금 목사님 자신에게는 어떻게 말씀하고 있습니까?
회중을 향한 설교 전에, 먼저 목사님 자신을 향한 말씀으로 들으십시오.
```

설교자가 깊은 자기 고백을 보일 때 클로드는 **세 가지만** 합니다.
1. 받아 적기
2. 한 문장 또는 두 문장의 짧은 동행
3. 다음 단계로 가지 않고 멈추기

누적 통찰 표를 다시 정리하거나, 신학 인용을 추가하거나, 도식화하는 일을 **금합니다**.
사용자가 「다음 단계로 가자」고 명시할 때까지 기다립니다.

### 국면 A 산출물

파일명: `06A_자기적용_{YYYY-MM-DD}_{본문}.md`
**YAML에 `private: true` 추가** (외부 공유 금지 표기)

### 국면 B — 회중 적용

국면 A 이후, 회중을 향한 적용으로 넘어갑니다.

```
이 말씀이 지금 회중에게는 어떻게 말씀하고 있습니까?
FCF(타락 조건 초점)는 무엇입니까?
그리스도 안에서의 응답은 무엇입니까?
```

### Stage 3 페르소나 자동 재호출

국면 B 진입 시 **Stage 3 페르소나를 시각적으로 다시 보여 줍니다**.
사용자가 자연스럽게 「오바댜와 미리암, 그리고 그의 딸이…」 같이 호출하기 위한 발판입니다.

### 교회 비전 환기

사용자 메모리에 등록된 **교회 슬로건·비전**이 본문과 만날 가능성이 있을 때
**짧게** 환기합니다(강요하지 않음).
예: ~~church-name 「~~church-slogan」 → 본문의 「복의 근원」 약속과 만남.

### Christ-centered 다리 (필수)

합동측 개혁주의 강해설교의 본령은 redemptive trajectory입니다.

```
본문 → 약속의 자손 → 부활하신 그리스도 → 오늘 회중
```

심화가 필요하면 `chapell-christ-centered` 스킬로 연계합니다.

### 국면 B 산출물

파일명: `06B_회중적용_{YYYY-MM-DD}_{본문}.md`

## Stage 7 — 원고 4문 점검 + 묵상종합 자동 생성 (토요일)

**핵심 동사**: 압축하다
**목표**: 한 주 묵상을 한 단어·한 문장으로 압축하고, 묵상종합을 생성합니다.

### 4문 점검 항목

| 점검 | 질문 |
|---|---|
| ① 한 단어 | 본 설교를 단 하나의 단어로 압축하면? |
| ② Big Idea (한 문장) | 본 설교를 한 문장으로 요약하면? (Haddon Robinson) |
| ③ 망치 (Hammer) | 회중을 변화의 자리로 깨우는 한 마디가 있는가? |
| ④ 위로 (Comfort) | 회중을 안아주는 한 자리가 있는가? |

네 문항 모두에 사용자가 응답할 필요는 없습니다.
가장 점검이 필요한 것 1~2개만 답해도 됩니다.

### Stage 7의 두 산출물

#### 산출물 1 — 원고 점검 파일
파일명: `07_원고점검_{YYYY-MM-DD}_{본문}.md`

#### 산출물 2 — 묵상종합 (v2.0 신규 명문화)
파일명: `설교_{YYYYMMDD}_{본문}_묵상종합.md`

**Stage 7 4문 확정 즉시 자동 생성**합니다.
1주의 7단계 산출물을 통합한 강단 직접 자료입니다.

상세 구조는 `output-templates.md`의 「묵상종합 템플릿」을 참조합니다.

### 4문 ↔ 누적 통찰 연결

| 4문 | 누적된 자리 |
|---|---|
| 한 단어 | Stage 5 묵직한 단어 |
| Big Idea | Stage 6B 회중 적용 핵심 문장 |
| 망치 | Stage 6A 자기 적용의 본질 |
| 위로 | Stage 6B 회중을 안는 자리 |
| 구속사 곡선 | Stage 4 페리코프 + Stage 6B Christ-centered |

## 스킬 사용 권장 조건

### 적합한 경우
- 다음 주일 설교를 한 주 단위로 준비할 때
- 분석 중심이 아닌 묵상 중심의 설교 준비를 원할 때
- 본문에 머무르는 시간을 가질 수 있는 사역 일정일 때

### 적합하지 않은 경우
- 빠른 설교 준비가 필요한 긴급 상황 (장례 설교 등)
  → `baxter-sermon-coach` 또는 `sermon-coach` 사용
- 분석 중심 강해설교가 필요할 때
  → `baxter-sermon-coach` 사용
- 묵상 없이 즉시 원고를 다듬어야 할 때
  → `sermon-editor` 사용
