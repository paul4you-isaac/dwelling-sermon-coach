# 산출물 관리 규칙 (v1.0.0)

단계 번호·이름·파일명의 기준은 `stage-map.md`입니다. 이 문서는 그 표를 따릅니다.

---

## 1. 산출물 저장 경로

본 스킬의 모든 산출물은 **설교자 Obsidian 볼트**에 저장합니다.
루트는 설정 `~/.config/dsc/dsc.config.json`의 **`vault_root`** 하나로 정합니다.

```
{config.vault_root}/
└── S_{다음주일_YYYYMMDD}/                       # 주차별 하위 폴더
    ├── 00_수집/                                 ← Stage 0 수집
    │   ├── passage.json                         # 본문 원문·번역 수집본
    │   ├── 주석/                                # 주석 자료 (Stage 4 1차청중 이후에만 노출)
    │   └── ask_log.jsonl                        # 작업창 질문 기록
    ├── 00_진행상황.md                           # 사람이 읽는 진행 현황
    ├── progress.json                            # 기계가 읽는 진행 상태
    ├── 01_본문만남_{설교일}_{본문}.md
    ├── 02_동행일지_{기간}_{본문}.md
    ├── 03_원어관찰.json                         # 원본 — 관찰 작업창이 기록
    ├── 03_원어관찰_{작업일}_{본문}.md           # 생성본 — 원본에서 자동 생성
    ├── 04_1차청중_{작업일}_{본문}.md
    ├── 05_맥락관찰_{작업일}_{본문}.md
    ├── 06_묵직한단어_{작업일}_{본문}.md
    ├── 07A_자기적용_{작업일}_{본문}.md          (private: true)
    ├── 07B_회중적용_{작업일}_{본문}.md
    ├── 08_원고점검_{작업일}_{본문}.md
    ├── 설교_{YYYYMMDD}_{본문}_묵상종합.md       ← Stage 8 원고점검 때 자동 생성
    ├── 설교_{YYYYMMDD}_{본문}_개요.md · .html   ← Stage 9 설교개요
    ├── Stage1_{본문}_본문만남.html
    ├── Stage4_{본문}_1차청중_페르소나.html
    └── Stage5_{본문}_페리코프3단.html
```

### 입력 자료 위치 (자유)

- 설정 `input_root`와 `materials_dirs`에 적은 폴더 (기사·책·유튜브·과거 설교 등)

### 폴더 경로 변경 이력

| 버전 | 산출물 루트 |
|---|---|
| v0.1.0~v2.0.1 | (프로젝트 폴더)/`output/` |
| v2.0.2 | (프로젝트 폴더)/`prep_sermon/` |
| v2.0.3~v0.4.0 | 볼트 안 `00-inbox/prep_sermon/` 또는 `주간묵상 설교준비/output/` (두 곳이 함께 쓰임) |
| **v1.0.0** | **설정 `vault_root` 하나** |

### 하위 규칙 불변성

루트 경로가 어디로 옮겨가도 **하위 폴더·파일명 규칙은 모두 그대로**:

- 서브폴더: `S_{다음주일_YYYYMMDD}/`
- 모든 Stage 마크다운·HTML 파일명 규칙
- 묵상종합 파일명 규칙
- YAML frontmatter 형식

**T_** = This week (이번 주일) · **S_** = Sermon (다음 주일 설교)

### 구판 주간 폴더

v1.0.0 이전에 만든 주간 폴더는 **이름을 바꾸지 않습니다.**
구판 파일명과 신판 파일명의 대응은 `stage-map.md`의 「구판 파일명 → 신판」 표를 봅니다.

### 설교일 자동 계산

설교일 미입력 시 오늘로부터 **다음 주일(일요일)**을 자동 계산합니다.
- 오늘이 일요일이면 다음 주 일요일
- 그 외 요일은 가장 가까운 다음 일요일

## 2. 파일명 규칙

```
{단계번호}_{단계명}_{날짜}_{본문}.md
```

예시:
- `01_본문만남_2026-05-17_시편105_1-22.md`
- `02_동행일지_2026-05-11_2026-05-13_시편105_1-22.md`
- `07A_자기적용_2026-05-15_시편105_1-22.md`

- 날짜 형식: `YYYY-MM-DD`
- 본문 형식: `성경책명장_시작절-끝절` (공백 없이 언더스코어 사용)
- 동행일지는 `시작일_종료일` 형식

### 날짜의 뜻

파일명의 날짜는 파일마다 뜻이 다릅니다. 실사용 그대로 둡니다.

| 파일 | 날짜 | 뜻 |
|---|---|---|
| `01_본문만남_…` | `{설교일}` | 이 본문으로 설교할 주일 |
| `02_동행일지_…` | `{기간}` | 동행을 시작한 날과 마친 날 |
| 그 밖의 단계 파일 (03~08) | `{작업일}` | 그 단계를 실제로 작업한 날 |
| 묵상종합·개요 | `{YYYYMMDD}` | 설교일 (주일) |

### 단계 명칭 통일

| 단계 | 정식 명칭 |
|---|---|
| 0 | 수집 |
| 1 | 본문만남 |
| 2 | 동행일지 |
| 3 | 원어관찰 |
| 4 | 1차청중 |
| 5 | 맥락관찰 |
| 6 | 묵직한단어 |
| 7A | 자기적용 |
| 7B | 회중적용 |
| 8 | 원고점검 |
| 9 | 설교개요 |

### 실사용 부속 파일 (허용 목록)

주간 폴더에는 위 산출물 외에 다음 부속 파일을 둘 수 있습니다.
설교자가 실제로 쓰는 파일이므로 정리·삭제 대상이 아닙니다.

| 부속 | 예 |
|---|---|
| `_낭독본` | `설교_{YYYYMMDD}_{본문}_낭독본.md` |
| `_원고_초고` | `설교_{YYYYMMDD}_{본문}_원고_초고.md` |
| `성경봉독_*` | `성경봉독_{본문}.html` |
| `설교프롬프터_*` | `설교프롬프터_{본문}.html` |

이 목록에 없는 파일은 만들지 않습니다.

## 3. YAML frontmatter 표준

### 단계별 산출물 공통

```yaml
---
dsc_version: 1.0.0
date: YYYY-MM-DD              # 작업일
sermon_date: YYYY-MM-DD       # 설교 예정일
text: 성경책 장:절
stage: (단계 번호)
session: (단계 이름)
preacher: {config.preacher}
church: {config.church}
status: dwelling | ready
tags:
  - dwelling-sermon-coach
  - (본문책 영문 슬러그)
  - (단계별 태그)
---
```

- 키는 모두 **snake_case**로 씁니다 (`sermon_date`, `big_idea`, `date_compiled`).
- 설교자 이름·교회 이름은 문서에 적지 않습니다. **설정(config)에서 채웁니다.**

### Stage별 태그 목록

| Stage | 태그 |
|---|---|
| 1 (본문만남) | `stage-1-encounter` |
| 2 (동행일지) | `stage-2-dwelling` |
| 3 (원어관찰) | `stage-3-original` |
| 4 (1차청중) | `stage-4-audience` |
| 5 (맥락관찰) | `stage-5-context` |
| 6 (묵직한단어) | `stage-6-keyword` |
| 7A (자기적용) | `stage-7a-self`, `private` |
| 7B (회중적용) | `stage-7b-congregation` |
| 8 (원고점검) | `stage-8-review` |
| 9 (설교개요) | `stage-9-outline` |
| 묵상종합 | `묵상종합` |

### Stage 7A 자기적용 특별 처리

자기 적용 산출물에는 반드시 `private: true`를 추가합니다.

```yaml
---
dsc_version: 1.0.0
date: YYYY-MM-DD
sermon_date: YYYY-MM-DD
text: 성경책 장:절
stage: 7
session: 자기적용
preacher: {config.preacher}
church: {config.church}
private: true
status: dwelling
tags:
  - dwelling-sermon-coach
  - stage-7a-self
  - private
---
```

이 산출물은 외부 공유를 전제하지 않습니다.

## 4. 원어관찰 생성본 템플릿 (v1.0.0 신규)

### 원본과 생성본

| 파일 | 역할 |
|---|---|
| `03_원어관찰.json` | **원본.** 관찰 작업창이 기록합니다. |
| `03_원어관찰_{작업일}_{본문}.md` | **생성본.** 원본에서 자동으로 만듭니다. |

생성본은 손으로 고치지 않습니다. 고칠 것은 **작업창에서** 고칩니다.
다음 생성 때 생성본은 원본 기준으로 다시 쓰입니다.

### YAML frontmatter

```yaml
---
dsc_version: 1.0.0
generated: true
stage: 3
session: 원어관찰
date: YYYY-MM-DD              # 작업일
sermon_date: YYYY-MM-DD
text: 성경책 장:절
preacher: {config.preacher}
church: {config.church}
tags:
  - dwelling-sermon-coach
  - (본문책 영문 슬러그)
  - stage-3-original
---
```

### 본문 구조

YAML 바로 다음 첫 줄은 반드시 아래 안내문입니다.

````markdown
> 이 파일은 관찰 작업창 기록에서 자동 생성됩니다. 작업창에서 수정하십시오.

# 원어관찰 — {본문}

## {구문 id}

**원문 구문**: {원어 구문}

**직역**【AI】: {직역}

**관찰**: {설교자 관찰 원문}

**해석**: {설교자 해석 원문}

**적용**: {설교자 적용 원문}

---

## {다음 구문 id}

(같은 형식 반복)
````

- 구문 id는 작업창의 id를 **그대로** 씁니다. 순서도 작업창 순서를 따릅니다.
- 다섯 칸의 내용은 설교자 글을 **한 글자도 바꾸지 않고** 옮깁니다.
- 설교자가 비워 둔 칸은 **비운 채로** 둡니다. AI가 채우지 않습니다.
- **직역은 Claude가 쓴 gloss**이므로 【AI】를 붙입니다.
  설교자가 작업창에서 직역을 직접 썼으면 그 직역은 표시 없이 그대로 둡니다.

## 5. 묵상종합 템플릿 (v2.0 신규, v2.0.7 원문 보존 규칙 통합)

### 원문 보존 원칙 (필수 — v2.0.7)

묵상종합 파일은 한 주 묵상의 **원본 기록의 결산**입니다. 각 Stage에서 사용자가 입력한
묵상 원문을 **변형·요약·재작성 없이 원본 그대로** 포함해야 합니다.

**보존 대상** (1·2·3·4·5·6·7B·8은 원문 그대로, 7A는 임베드만):
- Stage 1 본문만남 — 첫 단어 + 첫 반응 메모 원문
- Stage 2 동행일지 — 월·화 동행일지 원문 (details 블록 그대로) + 기본 관찰 6문 답 + 장면 나누기 원문
- Stage 3 원어관찰 — 절별 묵상 노트 원문 그대로. 구문 한 줄·직역·해설은 【AI】 표시 유지. `stage3_private: true`이면 노트는 옮기지 않음
- Stage 4 1차청중 — 사용자가 떠올린 페르소나 원문
- Stage 5 맥락관찰 — 앞·본문·뒤 페리코프를 보며 설교자가 말한 원문
- Stage 6 묵직한단어 — 묵직한 단어 발견 시 사용자 신학적 통찰 원문
- Stage 7A 자기적용 — **원문을 옮기지 않습니다.** 07A 파일을 임베드만 합니다 (아래 참조)
- Stage 7B 회중적용 — 회중 적용 원문
- Stage 8 원고점검 — 4문 응답 원문

**보존 형식**:
1. 짧은 원문 — 본문 안에 그대로 (인용부 「」)
2. 단락 원문 — 단락 단위로 그대로 포함
3. AI 요약 추가 시 — 요약 앞에 【AI】를 붙이고, 원문은 `<details>` 블록에 항상 보존

**금지 사항**:
- 사용자 원문의 핵심 표현을 다른 어휘로 바꾸지 않음
- 사용자의 호흡·강조·문장 길이 그대로
- 명백한 받아쓰기·구술 입력 오탈자만 최소 교정
- 「풀어 주는」 신학적 해설로 가공 금지

「누적 곡선 표」·「구속사 곡선」 같은 AI 추가 항목(【AI】 표시)은 묵상종합 후반부에만 배치합니다.

````markdown
**구속사 곡선**: {설교자가 쓴 곡선이면 원문, 아니면 【AI】 표시}
````

- 중괄호 칸은 모두 **원문 전체를 그대로** 옮깁니다. 「요약」 칸은 없습니다.
- 설교자가 비워 둔 칸은 비운 채로 둡니다. AI가 채우지 않습니다.
- **구속사 곡선**은 설교자가 쓴 곡선이면 원문, 아니면 【AI】 표시를 붙인 보조 문장입니다.
- Stage 3 원어관찰의 **구문 한 줄·직역·해설**은 Claude가 쓴 것이므로 【AI】를 붙입니다.
  설교자의 묵상 노트는 표시 없이 원문 그대로 둡니다.
- 설정 `stage3_private: true`(예전 이름 `stage3_apply_private`)이면 Stage 3 원어관찰의 **묵상 노트는 옮기지 않습니다.**
  그 자리에는 아래 두 줄만 둡니다.

```markdown
**적용**: 비공개 기록
![[03_원어관찰_{작업일}_{본문}]]
```

- Stage 7A 자기적용 칸은 **내용을 복사하지 않습니다.** Obsidian 임베드 한 줄과 안내 한 줄만 둡니다.
- 임베드는 Obsidian 안에서만 펼쳐집니다. 묵상종합을 밖으로 보내도 07A 원문은 따라가지 않습니다.

## 7. AI 문장 표시 — 【AI】

설교자가 쓴 글과 AI가 쓴 글은 **한눈에 구분**되어야 합니다.
v1.0.0부터 모든 산출물에서 AI 문장 표시를 **【AI】** 하나로 통일합니다.

| 형식 | 설교자 원문 | AI가 쓴 문장 |
|---|---|---|
| `.md` | 표시 없음 | `【AI】 문장` (줄 맨 앞) |
| `.html` | `.preacher-text` | `.claude-text` + 배지 `<span class="ai-badge">【AI】</span>` |
| `.html` 페르소나 | `.persona-block` 안의 `.preacher-text` | — |

```html
<p class="preacher-text">야곱은 자신의 험악한 130년을 기억합니다.</p>
<p class="claude-text"><span class="ai-badge">【AI】</span>복을 빌어줄 수 있는 것은 받은 복을 기억하기 때문입니다.</p>
```

- 구판의 `[클로드]`·`*[클로드] …*`·「클로드 제안」 표시는 쓰지 않습니다. 모두 【AI】로 바꿉니다.
- 클래스 이름 `.preacher-text`·`.claude-text`·`.persona-block`은 그대로 둡니다.
- 배지 클래스는 `.claude-badge`에서 **`.ai-badge`**로 바꿉니다.
- `.md`에서 AI 문장에 이탤릭을 쓰지 않습니다. 【AI】 표시만으로 구분합니다.
- AI 문장이 없는 칸은 설교자 원문만으로 완결입니다.
